# snax-forge bundle: vsum

A cluster with an accelerator generated by
[snax-forge](https://github.com/KULeuven-MICAS/snax-forge), and the program
that drives it, checked in so that `.github/workflows/snax-forge-ci.yml`
builds and runs it on every PR without a snax-forge checkout. The files are
snax-forge's output, untouched: vsum (a sum over the vector, the Chisel
`Accumulator`: one 64-bit lane, a pipelined fold, N = 64) on snax-forge's
`snax_forge` platform, made by snax-forge
`61d11b9386eb3d7727b95833dfc18e18ba0db6e1` (`bundle.json`).

- `snax_forge.hjson`: the cluster `snax_forge_cluster`. Its accelerator
  `snax_forge` brings its own CSR manager (`snax_disable_csr_manager`) and
  names its RTL's file list (`snax_forge_rtl: "rtl/files.f"`), which snaxgen
  turns into `generated/snax_forge.f`.
- `snax_forge_streamer.hjson`, `snax_forge_acc.hjson`: the two files the
  cluster's `$ref`s name (the streamer; the datapath block, read by
  SNAX-GVSoC only).
- `rtl/files.f` and the files it lists (`rtl/sv/`): the accelerator's RTL,
  `snax_forge_shell_wrapper` and its modules.
- `main.c`, `data.h`, `include/`: the program. `main.c` runs the task list
  (core 1 the DMA, core 0 the accelerator) and prints the `forge` lines;
  `data.h` holds the input and the golden sum (seed 0); `include/` the
  streamer's `streamer_csr_addr_map.h` and the accelerator's `acc_csr.h`.
  `sw/apps/snax-forge` builds it; snax-forge builds the same program for
  SNAX-GVSoC.
- `bundle.json`: the design point, the tag and the snax-forge commit.

## Run it

Verilator, from the repository root (as `snax-forge-ci.yml` does):

    make -C target/snitch_cluster rtl-gen CFG_OVERRIDE=cfg/snax_forge/vsum/snax_forge.hjson
    make -C target/snitch_cluster sw CFG_OVERRIDE=cfg/snax_forge/vsum/snax_forge.hjson
    make -C target/snitch_cluster snax-forge-sim SIM=vlt CFG_OVERRIDE=cfg/snax_forge/vsum/snax_forge.hjson
    make -C target/snitch_cluster snax-forge-run SIM=vlt CFG_OVERRIDE=cfg/snax_forge/vsum/snax_forge.hjson

Questa: `rtl-gen` and `vsim_preparation` in the development image (as for
any cluster), then the build and the run outside it with `bender` on `PATH`:

    make -C target/snitch_cluster rtl-gen CFG_OVERRIDE=cfg/snax_forge/vsum/snax_forge.hjson
    make -C target/snitch_cluster vsim_preparation CFG_OVERRIDE=cfg/snax_forge/vsum/snax_forge.hjson
    make -C target/snitch_cluster snax-forge-sim SIM=vsim CFG_OVERRIDE=cfg/snax_forge/vsum/snax_forge.hjson
    make -C target/snitch_cluster snax-forge-run SIM=vsim CFG_OVERRIDE=cfg/snax_forge/vsum/snax_forge.hjson

`snax-forge-run` builds the program first (`snax-forge-sw`, which also checks
`include/streamer_csr_addr_map.h` against the one snaxgen wrote), writes the
output to `target/snitch_cluster/logs/snax-forge-<vlt|vsim>.txt` beside the
traces, and fails on the program's nonzero exit code. `ELF=<path>` (absolute, or
relative to `target/snitch_cluster`) runs another ELF instead, such as the
one snax-forge built from the bundle.

Expected (Verilator and Questa alike, and SNAX-GVSoC's counter; CI checks
the counter line):

    forge data: 0 errors (1 words)
    forge counter sum_acc: 67
    forge errors: 0

## Refreshing it

In snax-forge (its `docs/RUN.md`, "Bundle for snax_cluster"):

    pixi run sandbox recipes/vsum.json
    pixi run design out/sandbox/vsum/2_bind.snaxdfg --platform platforms/snax_forge.json
    pixi run bundle out/design/vsum/design_point.json

then replace this folder's files (all but this README) with these from
`out/bundle/vsum/`: `snax_forge.hjson`, `snax_forge_streamer.hjson`,
`snax_forge_acc.hjson`, `bundle.json`, `main.c`, `data.h`, `include/`,
`rtl/files.f` and exactly the files `rtl/files.f` lists (not
`manifest.json`, which only SNAX-GVSoC reads). Update the commit above from
the new `bundle.json`.

# snax-forge bundle: vecadd

A cluster with an accelerator generated by
[snax-forge](https://github.com/KULeuven-MICAS/snax-forge), checked in so
that `.github/workflows/snax-forge-ci.yml` builds it on every PR without a
snax-forge checkout. The files are snax-forge's output, untouched: vecadd
(`elementwise_add`, 4 lanes of 64 bit) on snax-forge's `snax_forge` platform,
made by snax-forge `6f14d141d236e4eccab2b7572e5fa8621b0324d6`
(`bundle.json`).

- `snax_forge.hjson`: the cluster `snax_forge_cluster`. Its accelerator
  `snax_forge` brings its own CSR manager (`snax_disable_csr_manager`) and
  names its RTL's file list (`snax_forge_rtl: "rtl/files.f"`), which snaxgen
  turns into `generated/snax_forge.f`.
- `snax_forge_streamer.hjson`, `snax_forge_acc.hjson`: the two files the
  cluster's `$ref`s name (the streamer; the datapath block, read by
  SNAX-GVSoC only).
- `rtl/files.f` and the files it lists (`rtl/sv/`): the accelerator's RTL,
  `snax_forge_shell_wrapper` and its modules.
- `bundle.json`: the design point, the tag and the snax-forge commit.

Build it:

    make -C target/snitch_cluster rtl-gen CFG_OVERRIDE=cfg/snax_forge/vecadd/snax_forge.hjson
    make -C target/snitch_cluster bin/snitch_cluster.vlt CFG_OVERRIDE=cfg/snax_forge/vecadd/snax_forge.hjson

## Refreshing it

In snax-forge (its `docs/RUN.md`, "Bundle for snax_cluster"):

    pixi run sandbox recipes/vecadd.json
    pixi run design out/sandbox/vecadd/2_bind.snaxdfg --platform platforms/snax_forge.json
    pixi run bundle out/design/vecadd/design_point.json

then replace this folder's files (all but this README) with these from
`out/bundle/vecadd/`: `snax_forge.hjson`, `snax_forge_streamer.hjson`,
`snax_forge_acc.hjson`, `bundle.json`, `rtl/files.f` and exactly the files
`rtl/files.f` lists. Update the commit above from the new `bundle.json`.

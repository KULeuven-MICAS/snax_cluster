# snax-forge bundle: vsum_tree_i8

A cluster with an accelerator generated by
[snax-forge](https://github.com/KULeuven-MICAS/snax-forge), and the program
that drives it, checked in so that `.github/workflows/snax-forge-ci.yml`
builds and runs it on every PR without a snax-forge checkout. The files are
snax-forge's output, untouched: vsum_tree_i8 (a sum over the vector, the Chisel datapath `TreeAccumulate` under its nest controller: 8 lanes of int8, one 64-bit word a beat, each lane
sign-extended into an int64 sum, N = 64) on snax-forge's `snax_forge`
platform, made by snax-forge `162f8a5ee760bfec33b8aa60f96e99c78ecc6354`
(`bundle.json`).

- `snax_forge.hjson`: the cluster `snax_forge_cluster`. Its accelerator
  `snax_forge` brings its own CSR manager (`snax_disable_csr_manager`) and
  names its RTL's file list (`snax_forge_rtl: "rtl/files.f"`), which snaxgen
  turns into `generated/snax_forge.f`.
- `snax_forge_streamer.hjson`, `accelerator.json`: the two files the
  cluster's `$ref`s name (the streamer; the accelerator's one description,
  snax-forge C§17, read by SNAX-GVSoC only).
- `rtl/files.f` and the files it lists (`rtl/sv/`): the accelerator's RTL,
  `snax_forge_shell_wrapper` and its modules: `snax_forge_csr` (its CSRs),
  `snax_forge_ctrl` (a controller per group) and `snax_forge_datapath`. The
  wrapper's per-group `<group>_busy_o` and `<group>_done_o` pins are left
  unconnected (snax-forge open item 92).
- `main.c`, `data.h`, `include/`: the program. `main.c` runs the task list
  (core 1 the DMA, core 0 the accelerator) and prints the `forge` lines;
  `data.h` holds the input and the golden sum (seed 0); `include/` the
  streamer's `streamer_csr_addr_map.h` and the accelerator's `acc_csr.h`.
  `sw/apps/snax-forge` builds it; snax-forge builds the same program for
  SNAX-GVSoC.
- `bundle.json`: the design point, the tag and the snax-forge commit.

## Run it

Verilator, from the repository root (as `snax-forge-ci.yml` does):

    make -C target/snitch_cluster rtl-gen CFG_OVERRIDE=cfg/snax_forge/vsum_tree_i8/snax_forge.hjson
    make -C target/snitch_cluster snax-forge-sim SIM=vlt CFG_OVERRIDE=cfg/snax_forge/vsum_tree_i8/snax_forge.hjson
    make -C target/snitch_cluster snax-forge-run SIM=vlt CFG_OVERRIDE=cfg/snax_forge/vsum_tree_i8/snax_forge.hjson

Questa: `rtl-gen` and `vsim_preparation` in the development image (as for
any cluster), then the build and the run outside it with `bender` on `PATH`:

    make -C target/snitch_cluster rtl-gen CFG_OVERRIDE=cfg/snax_forge/vsum_tree_i8/snax_forge.hjson
    make -C target/snitch_cluster vsim_preparation CFG_OVERRIDE=cfg/snax_forge/vsum_tree_i8/snax_forge.hjson
    make -C target/snitch_cluster snax-forge-sim SIM=vsim CFG_OVERRIDE=cfg/snax_forge/vsum_tree_i8/snax_forge.hjson
    make -C target/snitch_cluster snax-forge-run SIM=vsim CFG_OVERRIDE=cfg/snax_forge/vsum_tree_i8/snax_forge.hjson

`snax-forge-run` builds the program first (`snax-forge-sw`, which also checks
`include/streamer_csr_addr_map.h` against the one snaxgen wrote), writes the
output to `target/snitch_cluster/logs/snax-forge-<vlt|vsim>.txt` beside the
traces, and fails on the program's nonzero exit code. `ELF=<path>` (absolute, or
relative to `target/snitch_cluster`) runs another ELF instead, such as the
one snax-forge built from the bundle.

Expected (Verilator and Questa alike, and SNAX-GVSoC's counters; CI checks
every counter line):

    forge data: 0 errors (1 words)
    forge counter sum_acc: 11
    forge errors: 0

## Refreshing it

In snax-forge (its `docs/RUN.md`, "Bundle for snax_cluster"):

    pixi run sandbox recipes/vsum_tree_i8.json
    pixi run design out/sandbox/vsum_tree_i8/2_bind.snaxdfg --platform platforms/snax_forge.json
    pixi run bundle out/design/vsum_tree_i8/design_point.json

then replace this folder's files (all but this README) with these from
`out/bundle/vsum_tree_i8/`: `snax_forge.hjson`, `snax_forge_streamer.hjson`,
`accelerator.json`, `bundle.json`, `main.c`, `data.h`,
`include/streamer_csr_addr_map.h` and `include/<name>_csr.h` (not the
runtime's cluster headers, which snaxgen writes),
`rtl/files.f` and exactly the files `rtl/files.f` lists (not
`manifest.json`, which only SNAX-GVSoC reads). Update the commit above from
the new `bundle.json`.
